# RUNART KOREA 모바일 앱 전환·배포 로드맵

작성 기준: 2026-08-31

## 결론

지금은 **앱스토어/구글플레이 제출 직전 단계가 아니라, 앱 전환을 전제로 웹 핵심 기능을 안정화하는 단계**다.

현재 RUNART KOREA는 Next.js + Supabase 기반으로 코스 탐색, 출발 준비, 주차/화장실, RUN+EAT, 라이브 러닝, GPS 기록 저장까지 핵심 사용자 흐름이 이미 존재한다. 따라서 별도 네이티브 앱을 처음부터 다시 만드는 것보다 **Capacitor 기반 하이브리드 앱으로 기존 웹 UI와 API를 최대한 재사용하고, GPS/백그라운드 동작만 네이티브 기능으로 보강하는 방식**을 1차 배포 전략으로 권장한다.

## 권장 앱 구조

### 1차: Capacitor 하이브리드 앱

- 기존 Next.js UI/디자인/비즈니스 로직 최대한 재사용
- Supabase 인증/DB/API 구조 유지
- iOS/Android 네이티브 프로젝트만 추가
- 위치 권한, 백그라운드 위치, 화면 유지, 앱 딥링크 등을 네이티브 브리지로 처리
- 카카오맵/네이버지도 외부 앱 호출 지원

이 방식이 현재 프로젝트에는 가장 적합하다. React Native/Flutter로 전면 재작성하면 현재 웹 기능을 거의 다시 구현해야 하므로 1차 출시에는 비용이 크다.

## 앱스토어 제출 전에 반드시 안정화할 항목

### A. 라이브 러닝 핵심

- 실외 5K 이상 실제 러닝 테스트
- GPS 거리 오차 확인
- 일시정지/재시작 안정성
- 화면 잠금/백그라운드 상태에서도 기록 유지
- 앱 강제종료/통신 끊김 시 임시 기록 복구
- GPS 포인트 저장량 및 배터리 사용량 점검
- 코스 이탈 경고 기준 실사용 검증

### B. 계정·데이터

- 회원가입/로그인/로그아웃 안정화
- 개인정보처리방침
- 위치정보 사용 목적 고지
- 회원 탈퇴 및 계정 삭제
- 사용자가 자신의 러닝 기록을 삭제할 수 있는 기능
- Supabase RLS 재점검

### C. 모바일 UX

- 코스 선택 → 출발 준비 → 지도 앱 길찾기 → 라이브 러닝 → 기록 저장 → RUN+EAT 흐름을 한 손으로 조작 가능하게 유지
- iPhone 작은 화면 및 Android 다양한 화면비 테스트
- 러닝 중 버튼 크기와 오조작 방지
- 네트워크 불안정 상태 메시지

### D. 스토어 준비

- 앱 이름 / 번들 ID 확정
- iOS Bundle ID 후보: `com.runart.korea`
- Android applicationId 후보: `com.runart.korea`
- 앱 아이콘 / 스플래시 이미지
- App Store / Google Play 스크린샷
- 개인정보처리방침 URL
- 위치 권한 설명 문구
- Apple Developer Program / Google Play Console 계정

## 권장 시점

### 지금 — Phase 0: 앱 준비 시작

지금부터 앱 구조를 고려해 개발한다.

- 웹 기능 추가 시 모바일/네이티브 재사용 가능 여부 확인
- 브라우저 전용 API 사용 지점 정리
- `navigator.geolocation`, Wake Lock, 외부 지도 스킴 같은 기능을 별도 어댑터 계층으로 분리할 준비
- 앱 배포 체크리스트 유지

### 다음 — Phase 1: 내부 테스트 앱

아래 조건을 만족하면 Capacitor 프로젝트를 생성한다.

- 코스 탐색/상세/출발 준비 흐름이 더 이상 크게 바뀌지 않음
- 라이브 러닝 저장 구조가 확정됨
- GPS 기록 저장이 실제 러닝 테스트에서 정상 동작함
- 인증/RLS가 안정적임

이 시점에는 App Store 제출을 하지 않고 개인 iPhone/Android에 설치 가능한 내부 테스트 빌드를 만든다.

### 그 다음 — Phase 2: TestFlight / Play Internal Testing

- iOS 실기기 백그라운드 GPS 테스트 통과
- Android 화면 잠금 및 배터리 최적화 환경 테스트 통과
- 기록 복구 기능 존재
- 위치 권한 UX 정리
- 개인정보 관련 페이지 준비

이 시점부터 TestFlight와 Google Play 내부 테스트를 시작한다.

### 최종 — Phase 3: 정식 스토어 제출

정식 출시 기준은 기능 개수가 아니라 **러닝 기록 신뢰도**다.

최소 다음 테스트를 통과한 뒤 제출한다.

- 서로 다른 기기 3대 이상
- 5km 이상 실제 러닝 10회 이상
- 화면 켠 상태 / 잠금 상태 / 앱 전환 상태 포함
- GPS 거리 오차가 사용 가능한 범위인지 확인
- 기록 누락/중복 저장 없음
- 앱 재실행 후 이전 기록 복구 가능

## 현재 프로젝트에서 가장 큰 앱 전환 포인트

현재 `components/RunMode.tsx`는 Web Geolocation API의 `navigator.geolocation.watchPosition()`과 Wake Lock API에 의존한다. 웹 브라우저에서는 화면 잠금이나 백그라운드 전환 시 GPS 추적 지속성이 OS 정책에 의해 제한될 수 있다.

따라서 네이티브 앱 전환의 가장 중요한 목적은 디자인을 바꾸는 것이 아니라 다음을 해결하는 것이다.

1. 백그라운드 GPS
2. 화면 잠금 상태 추적
3. 기록 임시 저장/복구
4. 앱 권한 처리
5. 지도 앱 딥링크
6. 필요 시 푸시 알림
